### 2-3. JavaScript 구현

| 기능 | 구현 방식 | 완성도 |
|------|-----------|--------|
| Canvas 파티클 네트워크 | `requestAnimationFrame` + 2D context | ✅ |
| 타이핑 효과 | `setTimeout` 재귀 함수 | ✅ |
| GSAP 입장 애니메이션 | 7단계 순차 stagger (`hero-right` → 연락처) | ✅ |
| GSAP magnetic | `overwrite:"auto"`, `elastic.out` | ✅ |
| 3D tilt + 스피닝 링 | `rotationX/Y`, `transformPerspective`, CSS `@keyframes` | ✅ |
| IntersectionObserver | 스크롤 카드 입장 애니메이션 | ✅ |
| 라이트박스 | 클릭·키보드·터치 스와이프 | ✅ |

7단계로 재조정한 세심함이 돋보인다.

## 4. 잘한 점 (Strengths)

### CSS 아키텍처
단순한 색상 변경을 넘어 **테마 파일 분리 + CSS 변수 토큰 시스템**을 구축한 것은  
실무에서도 바로 활용 가능한 수준이다. 5가지 테마 모두 다크 모드까지 지원한다.

### 이미지 생성 자동화
npm 패키지 없이 PowerShell `System.Drawing`(.NET GDI+)으로 OG 이미지를 프로그래밍으로  
생성한 점이 인상적이다. 도구의 한계를 창의적으로 해결한 접근이다.

### GSAP 개념 이해
단순히 애니메이션을 추가하는 수준을 넘어, `overwrite:"auto"`의 동작 원리를  
정확히 파악하고 float/magnetic 충돌 문제를 구조적으로 해결했다.

### Hero 리디자인
"촌스럽고 비어 보인다"는 피드백을 받고 좌우 분할 레이아웃·스피닝 링·상태 배지·  
스탯 행으로 완성도를 크게 높였다. 단순 수정이 아닌 구조 자체를 재설계한 점이 좋다.

### 체계적 문제 해결
GitHub Stats 깨짐 원인을 `curl`로 직접 HTTP 응답을 확인해 `DEPLOYMENT_PAUSED`로  
특정했고, 4종의 대체 서비스를 실제 응답 코드로 검증한 뒤 교체했다.  
QA 실무에서 체화된 **근거 기반 트러블슈팅 습관**이 개발에서도 그대로 나타났다.

### Git 커밋 습관
23개의 커밋이 각각 독립적인 기능을 담고 있어 히스토리 추적이 쉽다.  
두 리포지토리(`rest01`, `JIwonOh-omp`)를 병행 관리한 점도 인상적이다.

## 5. 개선할 점 (Areas for Improvement)

### 이미지 최적화
캐나다 사진 3장이 각 3~4MB 수준으로 웹 성능에 영향을 준다.  
→ `WebP` 포맷 변환 및 리사이징 처리를 추가하면 좋다.

### JavaScript 모듈화
`script.js`가 IIFE 함수 10개로 구성되어 있는데,  
규모가 커지면 ES Module(`import/export`) 방식으로 분리하는 것이 바람직하다.

### Form 요소 부재
현재 연락처는 이메일/전화 링크만 있다.  
향후 `<form>` 태그를 활용한 연락 폼(Formspree 등)을 추가하면  
포트폴리오 사이트로서 완성도가 높아진다.

### 프로젝트 섹션 보강
현재 프로젝트가 이 이력서 웹사이트 1개뿐이다.  
교육 과정에서 만드는 프로젝트를 꾸준히 추가해나가면 포트폴리오가 풍부해진다.
